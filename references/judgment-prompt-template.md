# 优先级判定提示词模板

> ⚠️ 历史模板（可选）：默认判定已改为本地引擎（`run_match.py`，零 token）。
> 只有在需要外部 Agent 复核判定时，才使用本模板。
>
> 旧版 Dashboard 的「一键判定」会读取本模板并填充占位符后复制给 AI 执行。
> 占位符：{raw_csv}（职位 CSV 绝对路径）、{result_dir}（判定输出目录绝对路径）

---

你正在执行 Boss 直聘岗位优先级判定任务。请严格按以下要求执行：

## 一、输入

- 数据文件（职位 CSV）：{raw_csv}
- 候选人画像：last（沿用最近一次引导的候选人画像；若不存在，则按 job-match-priority Skill 的 Step 0 先完成画像引导，再继续判定）

## 二、输出

- 输出目录：{result_dir}
- 必须生成一个判定结果 CSV，文件名规则：<输入CSV文件名>_判定结果.csv

## 三、输出 CSV 字段硬性约束（缺失任意必填列 = 任务失败，需重做）

1. **job_id** —— 必须与输入 CSV 的 job_id 完全一致（原样复制，不得修改、不得删行、不得增行；顺序可以与输入不同）
2. **优先级判断** —— 只能取值 `high` / `medium` / `low`（小写英文），每个岗位必须给出且不能为空
3. **优先级判断理由** —— 必填，每个岗位至少 30 字，说明与候选人画像的匹配依据
4. **匹配度** —— 0-100 的整数（百分比）
5. 能力条目得分 / 叠加信号 / 平均JD深度 / 平均候选人深度 —— 可选，但建议填写

> ⚠️ **已有判定结果的岗位不得覆盖**：若输入 CSV 中某 job_id 的「优先级判断」字段已有值（非空），则该岗位视为已完成判定，必须**原样保留**其优先级判断、匹配度、优先级判断理由等所有判定字段，不得修改。仅对「优先级判断」为空的岗位进行判定。

## 四、判定方法论

按 job-match-priority Skill 的 KSAO 加权评分流程执行：

1. 提取候选人的知识（K）、技能（S）、能力（A）、其他特质（O）
2. 逐岗位评分：对照 JD 逐条评估匹配度与深度
3. 加权汇总得出 高/中/低 三级优先级
4. 为每个岗位记录判断理由

## 五、完成标准（自检清单）

- [ ] 输出 CSV 的行数 == 输入 CSV 的行数（每个 job_id 都有判定）
- [ ] 所有 job_id 与输入 CSV 完全一致，无改动
- [ ] 每个岗位都有 优先级判断 和 优先级判断理由
- [ ] 文件以 utf-8-sig 编码写出（避免 Excel 打开乱码）
- [ ] 完成后汇报：总判断数、高/中/低分布、输出文件绝对路径
